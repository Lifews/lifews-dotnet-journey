# 什么是"提供程序(Provider)"？
"提供程序(Provider)" 在日志系统中指的是日志输出的具体目的地和处理方式。每个提供程序负责将日志消息发送到不同的地方。
如，控制台，是一个临时性提供程序；
如，文件系统，是最常用、真正持久化的日志提供程序。



# 使用日志记录有两种常见方式：
       1、直接创建LoggerFactory并配置"提供程序(Provider)"。
       优点：
       简单直接：不需要搭建完整的依赖注入框架，适用于小型应用或快速原型。
       控制力强：你可以完全控制LoggerFactory的创建和配置。
       轻量：没有额外的依赖注入容器的开销。
       缺点：
       生命周期管理：需要手动管理LoggerFactory和Logger的生命周期，确保资源正确释放。
       不易扩展：当需要更多服务（如配置、其他业务服务）时，需要自己构建容器。
       不符合现代应用设计：对于大型应用，使用依赖注入容器是更好的选择。
       
       2、通过Host（通用主机）来构建服务，并在DI容器中配置日志记录。
       优点：
       完整的依赖注入：可以在任何地方注入 ILogger<T>
       配置驱动：可以从 appsettings.json 文件读取配置
       服务生命周期管理：自动管理服务的创建和销毁
       可扩展性强：可以轻松添加其他服务（如 HttpClient、数据库上下文等）
       支持热重载：配置更改可动态生效
       统一管理：所有服务都在一个容器中管理
# 基本所有项目都应该有一个appsettings.json  但我们先不探索这个


# 日志记录器的许多功能，Serilog都是开创者和标准化者。
  事实上，微软很大程度上在跟随Serilog的脚步，在结构化日志记录上采纳了他的理念。
  因此后续的项目，我都会使用Serilog来做日志记录


# Serilog有一个庞大的Sinks家族。所谓Sinks(接收器)，就相当于其他日志记录器中的提供程序(Provider)。


#如何在日志记录器中保护敏感数据？
使用Nuget包--Destructurama.Attributed


#所有Sink都是同步推送的，如果想要异步推送，可以使用Nuget包--Serilog.Sinks.Async
Serilog.Sinks.Async--它可以把Sink都变成异步推送，只有当满足设定的条件时才会把日志推送到提供程序
