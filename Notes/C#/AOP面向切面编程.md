# AOP

**Aspect-Oriented Programming**	**面向切面编程**

**面向切面编程 (AOP)** 是一种编程范式（或编程思想），它允许开发者将散布在应用程序多个模块中的**横切关注点**（如日志记录、事务管理、安全性、性能监控等）**模块化**，并与核心业务逻辑**分离**。



## 为什么需要 AOP？

想象一下你在开发一个复杂的业务系统（比如电商系统），有很多核心业务类（如 `OrderService`, `UserService`, `ProductService` 等）。这些类专注于处理它们特定的业务逻辑（如创建订单、管理用户、更新产品信息）。

但是，除了核心业务逻辑，系统还需要处理一些**通用的、非业务性的功能**：

1. **日志记录：** 在方法调用前后记录日志。
2. **事务管理：** 确保数据库操作的原子性、一致性、隔离性、持久性（ACID）。
3. **安全控制：** 检查用户权限，决定是否允许执行某个方法。
4. **性能监控：** 统计方法的执行时间。
5. **异常处理：** 统一捕获和处理异常。
6. **缓存：** 在方法调用前检查缓存，在方法调用后更新缓存。
7. **数据校验：** 在方法执行前校验参数合法性。

这些功能被称为 **“横切关注点”**，因为它们**“横切”** 了多个核心业务模块。如果用传统的面向对象编程 (OOP) 来实现这些功能，会出现什么问题？

- **代码重复：** 你需要在每个需要这些功能的业务方法里（或附近）编写相似的日志、事务、安全等代码。
- **代码混乱：** 核心业务逻辑中混杂着大量非业务代码，降低了代码的可读性和可维护性。
- **难以维护：** 如果需要修改日志格式、事务策略或安全规则，你需要修改所有相关的业务类，工作量巨大且容易出错。
- **耦合度高：** 业务代码与这些通用功能代码紧密耦合在一起。



**AOP 如何解决这些问题？**

AOP 的核心思想是将这些横切关注点**提取出来**，封装到独立的模块中，称为 **“切面”**。然后，通过特定的机制，在程序运行的**合适时机**和**合适位置**（比如在某个方法调用前、后、抛出异常时等），**自动**地将这些切面代码**“织入”**到核心业务代码中。



## **AOP 的核心概念：**

1. **切面：** 横切关注点的模块化。它包含**通知**和**切点**。例如，你可以定义一个 `LoggingAspect`（日志切面）或 `TransactionAspect`（事务切面）。
2. **连接点：** 程序执行过程中可以插入切面的点。在基于方法拦截的 AOP（如 Spring AOP）中，连接点通常是**方法的调用**或**执行**。
3. **通知：** 切面在特定连接点执行的动作。定义了“**做什么**”和“**何时做**”。主要的通知类型有：
   - **前置通知：** 在目标方法**执行之前**执行（如权限检查、日志记录开始）。
   - **后置通知：** 在目标方法**成功执行之后**执行（如日志记录结束、清理资源）。*注意：无论方法是否成功结束都会执行的通知叫最终通知。*
   - **返回通知：** 在目标方法**成功执行并返回结果之后**执行（可以访问返回值）。
   - **异常通知：** 在目标方法**抛出异常时**执行（如记录错误日志、事务回滚）。
   - **环绕通知：** **包裹**目标方法的执行，可以在方法执行**前后**执行自定义行为，甚至可以决定是否执行目标方法（如性能监控、事务管理最常用）。
4. **切点：** 一个表达式，定义了“**在何处应用通知**”。它通过匹配规则（如方法签名、类名、注解等）选择一组连接点。通知与切点关联，共同定义了“在**哪里**（切点）**什么时候**（通知类型）**做什么**（通知代码）”。
5. **织入：** 将切面应用到目标对象并创建新的代理对象的过程。织入可以在不同的阶段发生：
   - **编译时：** 在源代码编译阶段织入（如 AspectJ）。
   - **类加载时：** 在类加载到 JVM 时织入（如 AspectJ）。
   - **运行时：** 在应用程序运行时动态生成代理对象（如 Spring AOP 主要使用的方式）。
6. **目标对象：** 被一个或多个切面所通知的对象。也就是那些包含核心业务逻辑的对象（如 `OrderServiceImpl`）。
7. **AOP 代理：** 由 AOP 框架创建的对象，用来实现切面契约（执行通知方法等）。在 Spring AOP 中，代理可以是 **JDK 动态代理**（基于接口）或 **CGLIB 代理**（基于类继承）。



## AOP 的典型应用场景

1. **声明式事务管理：** 使用 `@Transactional` 注解，背后的 AOP 会在方法执行前开启事务，在方法正常结束后提交事务，在抛出异常时回滚事务。
2. **日志记录：** 统一记录方法的入参、出参、执行时间、异常信息等。
3. **安全控制：** 在方法执行前检查用户权限（如 `@PreAuthorize`）。
4. **性能监控：** 统计方法执行耗时。
5. **缓存：** 方法执行前检查缓存，命中则直接返回；未命中则执行方法并将结果放入缓存。
6. **错误处理：** 统一捕获特定异常并转换或记录。
7. **数据校验：** 在方法执行前校验参数（如 `@Valid`）。



## AOP 的优点

- **减少重复代码：** 将通用功能集中到切面中。
- **提高模块化：** 横切关注点被清晰地模块化为切面。
- **增强可维护性：** 修改横切关注点逻辑只需要修改对应的切面。
- **提高可重用性：** 切面可以很容易地应用到不同的模块。
- **核心业务更清晰：** 业务类只包含核心逻辑，代码更干净、易读。
- **非侵入性：** 通常不需要修改目标业务类的源代码（通过代理实现）。
